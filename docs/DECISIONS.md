# Locked decisions

**Version:** 0.3.0

Change only with an explicit decision update. Prefer amending this table over silent drift.

| ID  | Decision                                                                                                                                                    | Why                                                                     |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| D1  | **Windows-first** Electron desktop app; other OS later if ever                                                                                              | Matches Explorer replacement use case                                   |
| D2  | **All app state in Electron `userData`** — never write MyFileExplorer sidecars into browsed folders                                                         | User folders stay clean; backup/app reset is clear                      |
| D3  | **Tabs** are the primary navigation unit; restore session on launch. Unreachable paths (unmounted / encrypted drives) stay open as **Offline** and auto-retry until available — never drop session tabs just because a volume is offline | Multi-folder workflows; reboot + late-mounted volumes must not lose tabs |
| D4  | **Curated context menu** — short allowlist, not Explorer’s full verb dump                                                                                   | Speed and clarity                                                       |
| D5  | Preview shows **A1111 / ComfyUI metadata when parseable** from common embeddings (PNG tEXt/iTXt etc.); omit rows if absent                                  | Core user need for AI image libraries                                   |
| D6  | Search acceleration via **opt-in indexed roots** + **SQLite FTS5** under userData                                                                           | Fast search where it matters; no mandatory whole-disk index             |
| D7  | **Del** → Windows Recycle Bin. Implementation: Electron `shell.trashItem` (IFileOperation) first, then `SHFileOperation` + `FOF_ALLOWUNDO`, then VisualBasic `SendToRecycleBin`. Refuse Del on volumes that cannot recycle. Directory watches are suspended for the duration so Chromium/Node cannot re-arm `ReadDirectoryChanges` mid-op. **Preview/media**: never `file://` to browsed paths. `mfe-media` buffers ≤128 MiB (source closed); larger non-AV uses userData scratch; **AV/PDF use HTTP byte-range (206)** so Chromium can play/seek — ≤128 MiB from memory, larger AV ranges the allowlisted path directly (no multi‑GB scratch). **Shift+Del** → permanent unlink with confirm when multi-select or directories. **In-app Recycle Bin** (tab-bar button): list bin contents in the normal file view (like search), Restore (Enter / context / banner), Empty Recycle Bin, Del permanently removes from the bin — never opens system Explorer | Spec-accurate recycle; avoid silent permanent deletes; never require Explorer |
| D8  | Themes = **CSS variables**; modes dark / light / custom token map; font family + size persisted                                                             | Comfort without theme-engine bloat                                      |
| D9  | **Typed preload IPC** + **Zod** validation; Result `{ ok, value \| error }` envelope                                                                        | Same reliability pattern as modern Electron apps                        |
| D10 | Thumbnails cached under userData keyed by **path + mtime + size**                                                                                           | Correct invalidation without hashing file bytes                         |
| D11 | Drag-drop: **Windows Explorer modifier conventions** (Ctrl=copy, default move same volume, etc.). **Right-button drag** opens a drop menu (Copy here / Move here / **Create shortcuts here** / Cancel) like Explorer — shortcuts are `.lnk` via WScript (works for `.exe` / `.bat` / `.lnk` / folders / any file). **Left-drag**: pointer gesture for in-app move/copy onto folders/tree/**tabs** (drop on a tab → that tab’s folder); when the pointer leaves the BrowserWindow, sync `webContents.startDrag` exports CF_HDROP to other apps. (Calling `startDrag` from HTML5 `dragstart` on Windows blocks in-app drops.) **Edge auto-scroll**: while a left/right drag is active, hovering near the top/bottom of the file list or folder tree scrolls that pane (Explorer parity). | Muscle memory; Explorer replacement must drag into other apps without breaking folder drops; tabs as sort categories |
| D12 | Renderer has **no Node integration**; filesystem only through main                                                                                          | Security                                                                |
| D13 | Default tab title = **folder name**; custom title optional and sticky until cleared. Optional **Lucide** tab icon + color (D32) | Renamed / labeled tabs for long-lived workspaces |
| D14 | Preview pane and splitter sizes are **session chrome** (persist in `session.json`)                                                                          | Restore layout                                                          |
| D15 | Unindexed search is allowed but must show **progress + cancel** and never claim indexed speed                                                               | Honest UX                                                               |
| D16 | Search DB uses Node's built-in **`node:sqlite`** (Electron ≥ 35) instead of `better-sqlite3`; FTS5 detected at runtime with **LIKE fallback**               | No native rebuild toolchain required; same schema either way            |
| D17 | **`userData` is always `%APPDATA%\MyFileExplorer`** for both `npm run dev` and installed builds. Optional `MFE_ISOLATED_USER_DATA=1` → repo `.dev-user-data/`; `MFE_USER_DATA` overrides the path. One-time migrate from legacy `.dev-user-data` / `my-file-explorer` when those profile files are newer | Same prefs while developing and after install; reinstall must not feel like a reset |
| D18 | Transfer conflicts: `fs:checkConflicts` returns compare details (size/dates/dims). Dialog shows **side-by-side** incoming vs existing (image thumbs when applicable). User may decide **per file** or apply **Skip all / Keep both all / Replace all**; non-conflicting sources always transfer | Informed Replace/Skip/Rename without guessing from names alone |
| D19 | **Single-instance** app; CLI `--reveal`/`--open` and `mfe://` protocol forward into the running process as a tab (file → parent + selection) | Lets other apps replace “Reveal in Explorer” without spawning Explorer |
| D20 | Quick access defaults to **Desktop / Downloads / Documents / Pictures** (not Home alone); user can pin/unpin folders; state in settings | Home-only was wasted space; Explorer-familiar shortcuts |
| D21 | File/folder **icons come from the Windows shell** via `SHGetFileInfo` (koffi) on win32, with `app.getFileIcon` fallback; cached under userData. Content thumbs stay for images/PSD; videos may use `!VIDTHUMB_CACHE` strips (D26). Folder cache keys include `desktop.ini` mtime so Dropbox/custom folder icons refresh | Explorer-accurate special folders + desktop.ini; Electron’s API alone collapses most folders to one glyph |
| D22 | **Per-folder view overrides** in settings (`folderViews`): view mode, sort, Details columns; optional **recursive** scope. Exact match wins, else longest recursive ancestor. Does not lock the tab — non-matching paths keep the tab’s baseline view + global columns | AI libraries and media folders need different layouts without sticky tab modes |
| D23 | **In-app undo/redo** (Ctrl+Z / Ctrl+Y) for trash, move, copy, rename, and new file/folder. Stack is session-memory only (max 30). Trash undo restores via Recycle Bin; permanent delete is not undoable | Explorer muscle memory; no dependency on system-wide Explorer undo |
| D24 | Per-tab **folder-tree expand/collapse** persists in `session.json` as `treeExpanded` (path list, capped). With path, selection, scroll, view/sort, and chrome splitters, relaunch restores the same workspace view | Exact “leave and come back” continuity |
| D25 | **Named workspace layouts** in settings (`layouts[]`): snapshot of tabs (path, title, icon, view/sort, rootPath, treeExpanded) + active tab index + chrome splitters + multi-view fields (D31: `viewLayout`, pane tab indexes, pane split ratios). Apply replaces the live tab set (new tab ids; history/selection/scroll cleared). Orthogonal to per-folder `folderViews` (D22). Cap 50. Manage via toolbar Layouts menu and Settings → Layouts | Task-specific workspaces (AI training, book editing, project coding) without juggling one session |
| D26 | **Video icon thumbs** from a sibling hidden `!VIDTHUMB_CACHE` folder: `{videoName}.thumb_1.jpg`…`thumb_20.jpg`, looped in icon/thumbnail views. Frame delay is settings `vidThumbFrameMs` (default 300, range 50–2000). Context menu can **generate missing** (this folder), **generate missing (all subfolders)**, or **regenerate** strips — 20 frames sampled evenly via bundled ffmpeg into that same cache convention. **Generate missing** treats a strip as present only when all 20 frames exist and are non-empty; partial/interrupted strips are cleared and redone. Missing/partial strips fall back to the shell icon. Media allowlist admits the cache dir when frames resolve | Matches existing external strip caches; optional in-app generation into the same convention |
| D27 | **In-app image editor** (Filerobot): crop/rotate/flip/resize/finetune/filters/annotate — no heal/clone/AI. Entry from preview Edit button and context menu. First save copies pristine bytes to `userData/image-originals/` (not a sidecar next to the file — D2); later saves keep that backup. **Revert to original** restores from userData | Non-destructive edit without polluting browsed folders |
| D28 | **File-op progress** in the status bar for copy, move, rename, trash, permanent delete, relocate, video-preview generation, and **ZIP compress**. Main emits throttled `op-progress` (work units + optional `bytesDone`/`bytesTotal` for large file copies ≥8 MiB). Status bar layout: **fixed progress bar → title → counts → truncating current name → Cancel**. Determinate when advancing; **indeterminate** while `done === 0` or total unknown. Renderer also shows indeterminate busy after **1 s** if an awaited FS op is still running and main has not yet reported real progress. **Cancel** (`fs:cancelOp`) stops between items (and mid large-file stream). Same-volume moves advance by whole roots (rename is atomic) with heartbeats; cross-volume/copy tick per file (and stream large files) | Honest feedback whenever the user is waiting; matches D15 honesty for search |
| D29 | **Search results use the normal file view** (`FileView`) — Details by default with a **search-only** sortable **Folder** column (containing path; not stacked under the name; not persisted / not in column picker), multi-select, preview, DnD, context menu. Search extras: **Open File Path** / **Open File in new tab** (in-app location). Banner above results. Not a separate results list | One interaction model; sort/filter by location like a real folder listing |
| D30 | **ZIP compress + extract + preview tree**: **Compress to ZIP file** / **Extract All…** as before (sibling `.zip` / folder, Explorer naming, zip-slip safe, progress + Cancel). Selecting a `.zip` shows preview `kind: 'archive'` with an expand/collapse **contents tree** (not a navigable virtual folder — still deferred). Listing reads the **central directory only** (archive byte size irrelevant); trees cap ~4000 nodes. **`.unitypackage`**: same tree UI (`archiveFormat: 'unitypackage'`), streams gzip+tar and maps GUID `pathname` → Unity paths; **no Extract All** (Unity owns import) | Explorer zip workflow + inspect-without-extract; Unity package inspect |
| D31 | **Multi-pane file views** (Q-Dir-style): session `viewLayout` `1` \| `2` (side-by-side) \| `4` (2×2). Each pane is a mini-explorer (own tree + files + nav) bound to at most one tab via `paneTabIds`. One tab cannot appear in two panes. Switching layout auto-fills empty slots from unassigned open tabs; leftover slots are drop targets (“Drop a tab here”). Focused pane syncs `activeTabId`; search / preview / keyboard nav target the focused pane. Shared preview; global tab bar + search. Persist layout + pane assignments + pane split ratios in `session.json`; named layouts (D25) snapshot the same | Side-by-side / grid workflows without multiple windows |
| D32 | **Tab chrome context menu** (right-click tab): Duplicate, Rename, Set/Change icon, Close. **Tab icons** are optional Lucide React glyphs (`icon.name` PascalCase + `icon.color` `#rrggbb`) persisted on the tab in `session.json` and named layouts (D25). Picker searches the full Lucide set with color presets + hex/native color input. Double-click title still renames | Color-code long-lived workspace tabs without inventing a custom icon pack |
| D33 | **In-pane video**: MP4/WebM/M4V play via `<video>` + byte-range `mfe-media`. MKV (and similar) remux/transcode to MP4 under `userData/video-remux/` when codecs allow. **`.avi` is strip-only** — no convert/player; show `!VIDTHUMB_CACHE` animation when present + **Open with default app**. Never write remux sidecars into browsed folders (D2) | AVI codecs (Xvid/DivX) aren’t Chromium-native; full re-encode is too heavy for preview |
